# Юрий · 0.6.0-m4

Проверочная локальная Windows-сборка с реализацией **UX-DOCX-01** и **M4-SEC-01**. Оба блока реализованы и проверены здесь, но пользовательская приёмка этой версии ещё не выполнена. **V1 не объявляется принятой.**

Рабочая 0.5.1-m4 и данные на ноутбуке автоматически не меняются. Модели, endpoint, ключ и лимиты B=1800 / C=4000 / D=4000 остаются в ваших существующих локальных настройках, установщик не должен задавать их заново.

## Что изменилось

### DOCX по шаблону

«Результаты → DOCX-черновик» или «В DOCX-черновик» у ответа:

1. Выберите претензию, иск общей юрисдикции или арбитражный иск — это разные доверенные шаблоны приложения, не универсальный бланк.
2. Заполните отдельные поля. Справочный ответ находится в раскрываемом блоке; можно перенести из него JSON с `templateId` и `fields`. Свободный текст не разносится по полям автоматически, чтобы не угадывать сведения. Пустую структуру JSON можно показать прямо там.
3. Пустое обязательное поле блокирует создание и называется в ошибке. Неизвестное обозначайте `[УТОЧНИТЬ: адрес]`; такая метка останется в черновике. Требования и приложения: одна строка — один пункт с нумерацией Word.
4. При необходимости выберите **один** вид расчёта: ст. 395 или договорная неустойка. Сумму, основание, периоды и ставки вводите явно. Автоматической проверки применимости и загрузки ставок нет. Даты расчёта включительно; округление каждого периода до копеек HALF_UP.
5. Рабочее оформление: A4, Times New Roman 14, интервал 1,5, поля 30/15/20/20 мм, отступ 1,25 см, таблица реквизитов без границ. Можно изменить профиль только этого документа. ГОСТ Р 7.0.97-2025 не выдаётся за универсальное обязательное правило для судебных документов.
6. Предпросмотр показывает текст и позволяет скачать обе формы до записи. «Подтверждаю создание DOCX» сохраняет пару: компактный DOCX и отдельный DOCX для сверки.
7. Компактный: основной документ и заключительная страница с краткими источниками/чек-листом. Сверочный: полные сохранённые фрагменты данного запроса, координаты и технический след. Это не полный текст всех исходных материалов.
8. «Открыть DOCX для печати» передаёт отдельную копию редактору с человекочитаемым именем. Если редактора нет — сохраните файл. Факт открытия/печати не подтверждается. Внешний вид и пагинацию проверьте в установленном Word. LibreOffice не требуется и не устанавливается.

Старые результаты не пересобираются задним числом. Для них сохраняются прежние байты и прежнее содержимое; отдельная сверочная форма не создаётся автоматически.

### Секретарь из обычного чата

Например: «Юрий, напомни мне в пятницу в 15-00 подать заявление в суд».

- Прямая команда обрабатывается локально, без модели B/D и без необходимости иметь API-ключ. Если зона ещё не подтверждена, сначала появится просьба подтвердить её.
- В чате появится **предложение**, не обещание выполненной записи. Откройте «Проверить предложение события».
- Для «в пятницу» дата намеренно не угадывается: выберите предложенную конкретную дату или введите другую. «На следующей неделе во вторник» определяет неделю явно. Несовпадение даты и дня недели требует уточнения.
- Проверьте название, дату, день недели, время и IANA-зону; при отсутствии времени явно выберите «весь день» либо введите время. Задайте смещения напоминаний, если они нужны: **пустой список = без напоминаний**.
- Только отдельная конечная кнопка подтверждения сохраняет событие. Отмена ничего не добавляет. Повторный requestId/повторное подтверждение не создают дубль.
- Это ограниченный разбор прямых команд, не универсальный разговорный агент. Доступна и прежняя кнопка «Дата в календарь». Повторяемость и расчёт процессуальных сроков не добавлялись. Старые ошибочные названия исправляйте отдельной подтверждаемой правкой.

Прежняя принятая компоновка чата, материалы и явные согласия, C/D, архив, история редакций и центр напоминаний сохранены.

## Безопасное обновление с установленной 0.5.1-m4

1. В работающей **0.5.1** сделайте резервный ZIP и сохраните его отдельно от рабочего пространства, желательно на другом носителе. ZIP не зашифрован и может содержать конфиденциальные документы; не прикладывайте его в чат без отдельной проверки.
2. Остановите именно вашу службу через её `stop.bat`. Не завершайте чужие процессы на 8765. После остановки дополнительно скопируйте всю папку рабочего пространства и сохраните старую папку программы.
3. Распакуйте **0.6.0 в новую отдельную папку программы**, не поверх старой `.venv` и не внутрь папки материалов. Не переносите `.venv` от старой версии.
4. `install.bat`, затем `start.bat`. Нужны Python **3.12/3.13 x64** и интернет для установки. Новые зависимости — docxtpl/Jinja2/MarkupSafe; Windows-wheels проверены на доступность для 3.12/3.13. Node, Docker, GPU и права администратора для обычной работы не нужны.
5. Используйте прежние настройки/рабочее пространство; не создавайте новое вместо старого. `http://127.0.0.1:8765/api/health` должен показать **0.6.0-m4**. Если показывает 0.5.1, продолжает работать старый экземпляр. Не запускайте две службы на одном пространстве.
6. Проверьте проекты, документы, старые результаты и модельные настройки, затем выполните `WINDOWS-ACCEPTANCE-0.6.0.md` на отдельном тестовом проекте/копии. Не используйте рабочие юридические документы для первых экспериментов.
7. Если нужны автоматические тесты: в папке новой программы ` .venv\Scripts\python.exe -m pip install -r requirements-dev.txt`, затем `.venv\Scripts\python.exe -m pytest -q`. Это отдельная установка тестовой зависимости pytest, не действие обычного запуска.

### Откат

Остановите 0.6.0. Сохраните её новые результаты отдельно, если они нужны. Запускайте старую программу с **копией пространства, сделанной до обновления**, а не с пространством, которое уже изменяла новая версия. Восстановление старого ZIP удалит из представления последующие изменения — сначала сохраните нужные данные. Автоматического понижения версии нет.

## Проверки и ограничения

- Здесь: **190 passed, 3 skipped**, Chromium-сценарии DOCX, секретаря и регрессий; подробности `TEST-REPORT.md`.
- Приёмка пользовательской 0.5.1 (137/137, компоновка чата, ручные M4-сценарии) остаётся историческим результатом, **не** проверкой 0.6.0 на Windows.
- Реальный сон Windows, офисная пагинация и печать не проверены здесь. Ранее имитация перерыва службы не считается настоящим сном ОС. Отсутствие LibreOffice не мешает обычной работе, но внешний вид DOCX надо проверить в доступном редакторе позже.
- Библиотеки извлечения не являются антивирусом или полноценной ОС-песочницей. Ограничения путей/размеров/таймаутов и проверки DOCX сохранены. Это не независимый аудит безопасности.
- Напоминания требуют работающей службы; во время сна/остановки доставки нет, пропущенные показываются в центре без массового повтора. Запрос показа ОС не означает прочтение.
- Временные копии редактора не импортируются и не удаляются автоматически после работы; считайте их конфиденциальными.
- Нет обучения/JSONL-корпуса, массового скачивания, автоматической передачи корпуса, юридического веб-поиска, локальной LLM, EXE, голоса, повторяемости или автозапуска Windows.
