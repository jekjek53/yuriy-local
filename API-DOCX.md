# DOCX API · 0.6.0-m4

Все прежние проверки Host/Origin/X-Yuriy-Token, выбранного пространства, проекта, архива и текущей генерации сохраняются. ID берите только из ответов API, не из приведённых пояснений.

## Каталог

`GET /api/document-templates` → `version`, `defaultProfile`, `templates`.

Три `templateId`: `pretension`, `claim_general`, `claim_arbitration`. У каждого имя, юрисдикция, роль и массив `{id,label,required}`. Точный набор полей берите из каталога; неизвестные поля отклоняются. Все обозначенные обязательные значения — непустые строки; явные `[УТОЧНИТЬ: …]` разрешены.

## Подготовка

`POST /api/projects/{pid}/results/docx-plan`:

```json
{
  "title":"Претензия по договору — проект",
  "templateId":"pretension",
  "fields":{
    "recipient_info":"[УТОЧНИТЬ: адресат и адрес]",
    "sender_info":"[УТОЧНИТЬ: заявитель и адрес]",
    "subject":"[УТОЧНИТЬ: предмет]",
    "circumstances":"[УТОЧНИТЬ: обстоятельства]",
    "grounds":"[УТОЧНИТЬ: основания]",
    "demands":"[УТОЧНИТЬ: требование]",
    "attachments":"[УТОЧНИТЬ: приложения]",
    "document_date":"[УТОЧНИТЬ: дата]",
    "signature":"[УТОЧНИТЬ: подписант]"
  },
  "calculation":{"method":"none"}
}
```

Необязательные `sourceMessageId` — сохранённый ответ ассистента текущего проекта, `profile` — переопределение ключей defaultProfile. Шрифты TNR/Arial/Calibri, размер 10–16, интервал 1–2, поля 10–40 мм, первая строка 0–20 мм; A4 неизменен. Поля до 20000 символов каждое, суммарно до 100000 и 1500 строк. Неподдерживаемая Markdown-разметка отклоняется, простая нормализуется; Jinja-выражения в данных не исполняются.

В ответе одноразовый `planId`, `revision`, `name`, `after` (текст, не вёрстка), `newSha256`, `reviewSha256`, `profile`, `templateName`, `sourceCount`, `unresolvedFields`, предупреждение. Байты и полная серверная metadata в ответ JSON не выдаются. План живёт 600 секунд; до 10 планов и 64 МиБ суммарных байтов двух форм.

- `GET /api/operations/{planId}/preview-file` — компактный DOCX.
- `GET /api/operations/{planId}/preview-file?format=review` — сверочный DOCX.
- `POST /api/operations/{planId}/confirm` с `{confirmed:true}` — сохраняет обе неизменяемые формы при совпадении ревизии. Неодноразовое повторение отклоняется. Потерю ответа можно сверить по `operations[].confirmationId`.
- `POST /api/operations/{planId}/discard` — отмена плана, без создания результата.

Создание документов не вызывает внешнюю модель. Структурированный ответ модели можно перенести в поля после проверки. Загружать и исполнять пользовательские шаблоны API не позволяет.

## Расчёт

Выбор `none` не допускает скрытых расчётных данных. Другие методы взаимоисключающие:

```json
{
  "method":"interest395",
  "principal":"10000",
  "basis":"[УТОЧНИТЬ: основание применимости процентов]",
  "periods":[{"start":"2024-01-01","end":"2024-01-10","annualRatePercent":"10","yearDays":366}]
}
```

Или `contract_penalty`, с `dailyRatePercent` вместо `annualRatePercent` и без `yearDays`. Суммы/ставки передавайте точными строками, не float. Периоды отсортированы, не пересекаются, даты начала/окончания включительно, до 50 периодов, каждый до 3660 дней. Для годовых процентов каждый период внутри одного года и с явно заданной календарной базой 365/366. Формула ст. 395: сумма × годовая ставка / 100 / база дней × число дней; договорная: сумма × дневная ставка / 100 × дни. Каждый период округляется до копеек HALF_UP, итог — сумма округлённых периодов. Правильность арифметики по вводу не подтверждает применимость нормы или полноту исходных данных; ставок и периодов по умолчанию нет.

## Результат и редактор

Старое обозначение `generatedBy=server-m3b` сохранено для совместимости защиты server-managed результатов. Новый `generatedWith=docxtpl-v1`, `templateData`, `templateVersion`, `templateSha256`, documentType/jurisdiction/role, fieldProvenance/sourceSnapshots. Отдельные `reviewArtifactId/reviewSha256` входят в backup/restore; новая миграция таблиц не нужна.

- `GET /api/projects/{pid}/results/{rid}/file?format=docx|review|txt` — проверяемые точные байты. По умолчанию compact. Имена передаются через UTF-8 Content-Disposition.
- `POST /api/projects/{pid}/results/{rid}/open-editor` с `{confirmed:true,sha256:"хеш выбранной формы",format:"docx"}`; `format=review` открывает сверочную форму. Создаётся отдельная копия с человеческим basename в случайном временном каталоге. Immutable result не меняется. Ответ `requested` означает лишь запрос ОС; не подтверждает открытия или печати.
- Для старых сохранённых DOCX без сверочной формы `format=review` даёт понятный отказ, а не пересборку. Исходные байты продолжают читаться и резервироваться.

Компактный документ не является независимой проверкой фактов и законодательства. Сверочная форма содержит сохранённые цитаты этого запроса, не обязательно все страницы исходного документа.
