# UX-DOCX-01 — реализация и проверки

Статус: реализовано в исходниках 0.6.0; технические проверки выполнены. Пользовательская приёмка Windows и внешний вид в установленном Word ещё не выполнены. Это не акт приёмки V1.

## Что изменено

- `docxtpl 0.20.2`, только три встроенных DOCX: претензия, иск общей юрисдикции, арбитражный иск. Реестр SHA проверяется перед подстановкой. Загрузка шаблонов пользователем не предусмотрена; это контроль целостности файлов программы, не криптографическая подпись издателя.
- Редактор отдельных полей; все обязательные значения проверяются до открытия шаблона. Пустые поля перечисляются по именам. `[УТОЧНИТЬ: …]` сохраняется. Поля можно заполнить вручную или перенести из JSON ответа после проверки. Автоматического семантического разнесения произвольного текста нет: цель — не угадывать сведения.
- Роль, юрисдикция, вид и версия шаблона, SHA шаблона, происхождение полей и снимки источников сохраняются с результатом. Метка `source-answer` означает точное наличие введённого поля в выбранном ответе, а не доказанность факта. Остальное — ввод, подтверждённый пользователем. Связь с источниками хранится отдельно; автоматическая атрибуция каждого факта документу не заявляется.
- Значения передаются как экранированные данные одним проходом. `{{7*7}}` и `{% include ... %}` остаются буквальным текстом. HTML не исполняется. Известный Markdown преобразуется в обычный текст; таблицы/блоки кода требуют ручного преобразования, а не сомнительного автоформатирования.
- A4, Times New Roman 14, интервал 1,5, поля 30/15/20/20 мм, первая строка 12,5 мм. Самостоятельные стили; реквизиты в правой ячейке таблицы без границ. Требования и приложения — отдельные нумерованные списки Word. Профиль можно изменить для конкретного документа.
- Компактная форма по умолчанию: основной документ и заключительная служебная страница с источниками/чек-листом. Явный разрыв страницы проверен в OOXML. Очень длинные реквизиты или служебный текст могут занять больше страницы: окончательную пагинацию устанавливает Word, её надо проверить в редакторе.
- Сверочная форма: отдельные неизменяемые байты DOCX, полные сохранённые цитаты, координаты, IDs, SHA, сведения извлечения и проверки C. «Полные» здесь — сохранённые фрагменты данного запроса, не весь исходный документ.
- Обе формы доступны до подтверждения и после сохранения. Одна операция подтверждает пару; хеши, backup/restore, защита от внешней подмены и одноразовое подтверждение сохранены. Старые DOCX не перевёрстываются задним числом.
- Человекочитаемый basename передаётся редактору; случайный ID теперь у каталога временной копии, не у имени файла. Отдельная копия не импортируется обратно автоматически.
- Проценты по ст. 395 и договорная неустойка — взаимоисключающие режимы с разными полями ставок и основаниями. Денежная арифметика Decimal; даты включительно, округление каждого периода до копеек HALF_UP. Ставки, периоды и применимость пользователь задаёт явно. Для годовых процентов период разделяется по годам и базе 365/366. Автоматической юридической экспертизы расчёта, загрузки ставок, учёта платежей или снижения неустойки нет.
- Ориентир в интерфейсе: ГОСТ Р 7.0.97-2025; не универсальное обязательное оформление судебных документов.

## Выполненные проверки

1. Полный pytest на этапе DOCX: **160 passed, 3 skipped**. Три существующих платформенных пропуска не засчитываются как проверки Windows.
2. 26 новых случаев `tests/test_legal_drafts.py`: три шаблона, параметры OOXML, разрыв страницы, таблица/стили/нумерация, буквальный Jinja, Markdown, пустые поля до сборки, неизвестные схемы, подмена шаблона, индивидуальный профиль, отдельные формы и доказательность, exact backup/restore, подмена сверочного файла, отдельные расчёты, отсутствие данных расчёта, человеческое имя редактора.
3. Адаптированы старые M3b/M4 тесты: тестовый helper теперь собирает поля. Сервер не принимает старый универсальный `title+text` как новый юридический документ. Сохранённые старые результаты читаются как раньше.
4. Chromium `ui_m3b.cjs`: PASS — C, DOCX, редактирование, история, точные байты скачивания, размеры 360/768/1440.
5. Chromium `ui_m4.cjs`: PASS — регрессии секретаря, архива, версий, безопасной HTML-печати и отмены.
6. Chromium `ui_legal_drafts.cjs`: PASS — пустое поле блокирует, три профиля, JSON переносится как данные, два предпросмотра/скачивания с точными байтами, имя в аргументе скачивания, fallback редактора, адаптивность, нет JS-ошибок.
7. `node --check` модуля: PASS. Скриншот интерфейса просмотрен; после этого поле названия приведено к общему стилю.

Особенность данного headless Chromium: для blob-загрузки фактическое `suggestedFilename` возвращалось как `download`, хотя `a.download` получал правильное русское имя. Проверены аргумент `saveBlob`, имя в API и реальная ветка формирования временного файла через имитацию Windows. Фактическое скачивание/открытие с русским именем на ноутбуке входит в ручную приёмку.

В конце добавлен ещё один тест совместимости: старый DOCX читается и проходит backup/restore без перепаковки; всего новых DOCX-случаев 27. Финальная совокупная проверка двух блоков и чистой распаковки — 190 passed / 3 skipped, все шесть браузерных сценариев PASS (TEST-REPORT.md).

## Что не проверено / не запускалось

- Нет установленного Office: визуальная пагинация, переносы и реальная печать не подтверждены. LibreOffice не устанавливался.
- Windows-открытие проверено заглушкой, не реальным приложением на ноутбуке.
- Нет fine-tuning, JSONL-корпуса, массового скачивания, передачи корпуса или скрытого внешнего API-вызова при сборке.
- M4-SEC-01 проверяется и описывается отдельно; этот отчёт его не закрывает.
