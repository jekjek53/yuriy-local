# Принятая база перед M4 · 0.4.0-m3b

Источник — сообщения пользователя о локальной приёмке Windows. Разработчик в этой среде не подключался к ноутбуку, не читал указанные локальные файлы и не выполнял эти проверки самостоятельно.

## Закрыто по отчёту пользователя

- RELEASE-MANIFEST: **42/42** файлов совпали; Windows pytest: **113/113**.
- Обновление с backup `20261120-114730-a65ce63b.zip` и отдельной копией; служба 0.4.0-m3b.
- Полный API-цикл правки, авто-backup, неизменность прежнего blob, новые SHA и скачивание «до».
- Реальный платный C: завершённый частичный отчёт с честными checkedChars/wholeAnswer/sourceCount и legalPrimarySourceVerification=false; отчёт не заявлял первичную правовую верификацию.
- DOCX API-цикл: SHA предпросмотра/артефакта, TXT и структурное открытие python-docx, пометка «Черновик», источники, чек-лист и сведения о C.
- UI-обход: правка → diff/SHA → подтверждение → журнал; PDF/HTML корректно не редактируются; отдельный реальный C с честным limited; DOCX-предпросмотр/карточка подтверждения.
- UI-вызов C достиг общего лимита при пустом отдельном C. Это признано настройкой, не дефектом. Пользователь затем установил **B=1800, C=4000, D=4000**.
- Пользователь закрыл **полную приёмку M3b**. Новых дефектов продукта в отчётах не заявлено.

## Согласованное исключение

Визуальная вёрстка/печать DOCX в офисном редакторе отложена: Word/LibreOffice на машине отсутствуют. LibreOffice не устанавливается без отдельного согласования. Структурное открытие DOCX не подменяет визуальную проверку.

Эта запись фиксирует статус принятой базы. Она не означает, что M4 уже проверена или принята на Windows.
