# Обновление до 0.1.1-m1

Исправление по вашему файлу `M1-Windows-отчёт.md`: D1 (блокирующий отказ путей), D2 (поиск Python), D3 (кодировка теста). Новые функции агента в это обновление не входят.

## Безопасное обновление

1. Остановите старую службу через её `stop.bat` либо Ctrl+C в окне службы. Закрытия вкладки браузера недостаточно.
2. Если в рабочем пространстве уже есть данные, при остановленной службе скопируйте **всю папку пространства** в резервное место средствами Проводника. Не удаляйте `.yuriy`.
3. Распакуйте новый архив **в новую папку программы**, не поверх рабочего пространства и не внутрь старой `.venv`.
4. Запустите `install.bat`. Он сначала попробует Python Launcher, затем `python` и `python3` из PATH. Совместимы Python 3.12/3.13 x64.
5. Если ваш бандлованный Python не зарегистрирован ни в Launcher, ни в PATH, откройте командную строку в новой папке программы и выполните:

```bat
install.bat "C:\настоящий путь\к\python.exe"
```

Замените пример настоящим путём. Установщик выводит найденный исполняемый файл и версию перед созданием окружения. Python 3.14 пока сознательно не принимается: совместимость всей конфигурации с ним не проверена.

6. Запустите `start.bat`. Путь к прежнему пространству остаётся в `%LOCALAPPDATA%\YuriyLocal\config.json`. Если папка уже выбрана, приложение должно открыть её без очистки данных. Если выбор не был завершён из-за D1, повторите его.
7. Проверьте в браузере `http://127.0.0.1:8765/api/health`: поле `version` должно быть **`0.1.1-m1`**. Если там `0.1.0-m1`, всё ещё работает старая служба — остановите её.

Схема базы и формат резервных копий не менялись; миграции и удаление старой базы не требуются.

## Что перепроверить на Windows

Из новой папки программы:

```bat
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

Тестов стало больше. В Linux результат: **37 passed, 1 skipped**. На Windows junction-тест должен выполниться, если NTFS и права позволяют создать junction; иначе он будет пропущен с причиной. Количество пропусков может отличаться из-за разрешения на создание symlink.

Затем пройдите пользовательский чек-лист из README: проекты → сообщение/черновик → импорт/скачивание файла → заметка → событие → архив → перезапуск → резервная копия и восстановление на тестовых данных.
