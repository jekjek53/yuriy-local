# Проверка 0.5.0-m4

## Фактический результат

**Проверочная M4, не завершённая Windows-приёмка и не объявление принятой V1.**

- Linux / Python 3.13: `python -m pytest -q` → **134 passed, 3 skipped**, одно унаследованное предупреждение Starlette об AnyIO BlockingPortal. Последний полный прогон до упаковки: 9.79 с.
- Добавлено **24** серверных теста M4 поверх 110 passed базы M3b. Прежние тесты не удалялись.
- Три пропуска: настоящие Windows DPAPI, junction и Job Object. Новые вызовы системных уведомлений/редактора в автоматических тестах подменяются; успешные тесты этой ветки не являются фактическим показом уведомления Windows.
- JavaScript, собранный локальным сервером из index.html + m4.js, проверен `node --check`; Python compileall — без ошибок.
- tzdata 2026.6 доступна как универсальный wheel и скачана. Это не Windows-исполнение.

## Серверные сценарии M4

1. Явные даты, относительные дни относительно IANA/момента, отсутствие выдуманного времени/года, неоднозначность и процессуальные предупреждения.
2. Samara→UTC, DST gap/overlap, неизвестная зона/время.
3. До confirm нет события, обязательное подтверждение, одноразовость и защита от подмены state; новая редакция события.
4. TTL/ревизия/архив/отмена карточки.
5. «Весь день» без startsAt; обязательное отдельное время напоминания; неверные смещения/окончание отклоняются.
6. Происхождение из сообщения и документа — реальные ID/снимки; подделанный фрагмент отклоняется, платного вызова при предложении нет.
7. Срабатывание один раз, перезапуск/явный просмотр; missed после большого перерыва без системного шквала.
8. Изменение/отмена расписания аннулирует прежнее; ошибка механизма показа не приводит к автоповтору, центр остаётся.
9. Явный архив keep/cancel, отменённое само не возобновляется.
10. Backup/restore настроек/квитанций/отметок и аннулирование карточек.
11. TXT/BOM/CRLF: просмотр и побайтовое восстановление через новый fileId/журнал.
12. DOCX: просмотр и возврат точных байтов без повторного find/replace.
13. Подтверждение/хеш DOCX перед передачей редактору; неизвестный формат/внешние relationships отклоняются.
14. Отдельная копия для редактора и запасной сценарий при отсутствии ассоциации, **OS-вызов подменён**.
15. Фиксированная PowerShell-команда, без shell=True и включения пользовательского текста, timeout/неопределённый статус показа, **процесс подменён**.
16. Фоновый lifecycle вызывается без браузерного запроса.
17. Смена зоны по умолчанию не двигает прежнее событие; legacy не получает расписание само.
18. Напоминание «весь день» использует явные локальные часы.
19. Сверка после подтверждения не поглощает новое срабатывание; название/заметка не создают повторный ключ расписания.
20. Детерминированная гонка SSE между yield теперь отдаёт финальный done=true.

Это группировка 24 тестовых функций, не 20 отдельных ручных приёмок Windows.

## Не выполнено здесь

- Установка/запуск **M4** на целевом Windows-ноутбуке, повторный DPAPI/junction/Job Object текущей сборки.
- Фактический Windows NotifyIcon/уведомления ОС, открытый/закрытый браузер на ноутбуке, настоящий сон/пробуждение/перезапуск службы в этих условиях.
- Настоящий системный диалог печати и его отмена, ассоциация DOCX, визуальная вёрстка/печать в редакторе. LibreOffice не установлен и не требуется устанавливать без согласования.
- Платный API на M4, качество реального ответа моделей и реальные сетевые задержки; M4 не добавляет платный вызов секретаря.
- Новые нагрузочные замеры сотен проектов/тысяч событий, внезапное отключение питания/отказ физического диска.

Принятая M3b: пользователь сообщил 113/113 на Windows и полную функциональную/UI-приёмку, затем лимиты B=1800/C=4000/D=4000. Это относится к **0.4.0-m3b**, не подменяет проверку M4; запись — ACCEPTANCE-M3b.md.

## Воспроизведение и приёмка

`python -m pip install -r requirements-dev.txt` → `python -m pytest -q`.

Browser scripts требуют отдельно Node/Playwright Chromium. Запускать только с `tests.mock_server:factory`, отдельным новым `YURIY_TEST_RUNTIME` и `YURIY_TEST_URL`, не против рабочей 8765. Каждый сценарий меняет тестовое состояние. Runtime/зависимости браузера в релизный ZIP не входят.

Целевая матрица ТЗ №16–19, настройки, сон и печать: **WINDOWS-ACCEPTANCE-M4.md**. Новые дефекты и границы: **NEW-DEFECTS-M4.md**. До завершения этой приёмки формулировка статуса — «M4 передана на Windows-приёмку», не «V1 принята».
