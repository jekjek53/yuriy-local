# Юрий · 0.5.1-m4

## Обновление компоновки чата

В 0.5.1: компактная шапка в чате, растущее поле ввода, раскрывающиеся материалы с постоянно видимым статусом согласия и кнопка «Развернуть чат» / Esc. Состояние согласия, запросы моделей, данные и лимиты не меняются при переключении вида. Фокусный режим не сохраняется на диске и сам не включается после перезапуска.

Если уже установлена 0.5.0-m4: сделайте ZIP и отдельную копию пространства, остановите службу и установите 0.5.1 в новую папку программы с тем же пространством/настройками. Не копируйте только HTML: новые CSS/JS локально подставляет сервер. Если остаётесь на M3b, ниже обычный порядок перехода к M4. Отчёт именно UI-исправления — CHAT-LAYOUT-UPDATE.md и текущий TEST-REPORT.md.

**M4 — «Секретарь и выпуск V1», проверочная сборка для приёмки Windows.** V1 ещё не объявлена принятой. Основа — принятая пользователем 0.4.0-m3b. Рабочая установка на ноутбуке этой поставкой автоматически не меняется.

Реализованы подтверждаемые события, напоминания службы и их центр, просмотр/возврат редакций, безопасный предпросмотр печати и передача DOCX редактору. Здесь выполнены Linux/Python/Chromium и имитация Windows-вызовов. **Настоящий показ уведомлений, сон Windows, офисная печать и системный диалог печати не объявляются проверенными.**

## Обновление с принятой M3b

1. В **0.4.0-m3b** создайте резервный ZIP. Сохраните отдельную копию вне рабочего пространства, желательно на другом носителе. Остановив службу, можно дополнительно скопировать всю папку пространства.
2. `stop.bat` старой программы. Не завершайте чужие процессы на порту 8765.
3. Распакуйте M4 **в новую папку программы**. Не поверх прежней `.venv`, не в пространство с материалами. Старая папка программы остаётся для отката.
4. Выполните `install.bat`, затем `start.bat`. Требуются Python **3.12/3.13 x64** и интернет для установки. В обычной работе Node, Docker, GPU и администратор не нужны.
5. `http://127.0.0.1:8765/api/health` должен показать **0.5.1-m4**. Старый экземпляр при повторном start не обновляется — его нужно остановить.
6. Проверьте проекты, документы, результаты и настройки моделей. M4 не меняет endpoint/ключ/лимиты B/C/D. Принятые пользовательские B=1800, C=4000, D=4000 остаются в локальных настройках, не зашиваются в сборку.
7. Первую проверку делайте на отдельном тестовом проекте с вымышленными сведениями. Выполните `WINDOWS-ACCEPTANCE-M4.md`.

Новая зависимость — **tzdata 2026.6** для IANA-зон в Windows; её универсальный wheel доступен и скачан при проверке, но Windows-установка здесь не выполнялась. Python 3.14 этой конфигурацией не поддержан испытаниями.

### Данные и откат

Основная схема SQLite остаётся **1**, формат state **2**: таблицы не меняются. Старые события не удаляются, не сдвигаются и не получают напоминания автоматически. Для включения расписания откройте старое событие, проверьте зону/поля, задайте напоминания и подтвердите карточку. Старое время трактуется как прежняя Europe/Samara.

Новые события содержат UTC, зону, происхождение и подтверждение; настройки/квитанции напоминаний находятся в meta основной SQLite и входят в backup. При чтении старой копии без этих настроек секретарь снова попросит подтвердить зону. Индекс документов, как раньше, восстанавливаемый и в ZIP не входит.

**Откат к 0.4.0 делайте на копии пространства ДО M4**, а не старым кодом на изменённой папке M4. Старый код не знает новых событий/расписаний. Остановите M4, верните отдельную дообновлённую папку пространства и старую программу. Если меняете путь пространства, локально укажите нужный абсолютный `workspace` в `%LOCALAPPDATA%\YuriyLocal\config.json` при остановленной службе. Не публикуйте соседние key/running-файлы.

## 1. События из поручений и фрагментов

Точки входа:

- «Чат» → **«＋ Дата в календарь»**: вставьте поручение/фрагмент;
- **«Предложить событие»** у сохранённого сообщения;
- «Документы» → «Текст» → **«Предложить событие из фрагмента»**;
- «События» → **«＋ Событие»** для ручного ввода.

При первом использовании явно подтвердите предложенную **Europe/Samara** либо другую IANA-зону. Это значение по умолчанию для новых событий, не команда переносить ранее записанные заседания. Существующие дата, время, зона и UTC не меняются при смене настройки.

### Что распознаётся

Разбор **локальный**, без дополнительного вызова модели и без передачи календаря провайдеру. Поддержаны явные `YYYY-MM-DD`, `DD.MM.YYYY`, `HH:MM` и слова «сегодня», «завтра», «послезавтра». Показываются абсолютная дата и опорная дата/зона разбора.

Это намеренно не универсальное понимание свободного текста. Несколько дат/времён, дата без года, «через N рабочих дней», «в следующий четверг», время словами и сложные формулировки требуют ручного уточнения. Если дата не определена — поле пустое; год и процессуальный срок не угадываются. Неверная календарная дата отклоняется.

Если время не найдено — «весь день», без вымышленного часа. У поручения длиннее 5000 символов можно выбрать/вставить нужный фрагмент; для длинного сообщения сначала открывается выборка с явным предупреждением об охвате. Первые 5000 символов предзаполнены, их можно заменить нужным точным фрагментом. Это не полный анализ сообщения. Фрагменты документов ограничены прежним размером извлечённых chunks.

### Подтверждение

Проверьте проект, название, абсолютную дату, время/«весь день», IANA-зону, тип, статус, окончание, место/суд, номер дела, заметку, напоминания и происхождение. Затем **«Проверить карточку»** → отдельное окно **«Подтверждаю все поля и сохранение»**.

До последнего подтверждения событие не сохраняется. Карточка действует 10 минут, одноразовая, связана с точными полями/ревизией состояния; смена окна/ревизии требует новой карточки. Модель не может подтвердить действие. При потере HTTP-ответа UI сверяет квитанцию в состоянии, а не незаметно создаёт второй экземпляр.

Происхождение — ручной ввод, локальное предложение из поручения, сообщение с ID/SHA либо извлечённый фрагмент с ID файла, версией текста, SHA и координатой. **Сведения источника не становятся доказанным фактом только из-за переноса в календарь.** При редактировании сохраняется исходное происхождение, изменения полей явно подтверждаются.

Процессуальные сроки — только черновик с предупреждением. Приложение не определяет применимую норму, начальный момент, праздничные переносы и правила исчисления. Даже подтверждённая пользователем карточка не является гарантией соблюдения срока.

### Время и статусы

Временные события хранят `startsAt/endsAt` в UTC и IANA-зону. События «весь день» хранят календарную дату, `startsAt=null`: она не превращается в полночь UTC. Для неоднозначного времени сезонного перехода есть первое/второе вхождение; несуществующее местное время отклоняется.

Статусы: запланировано, выполнено, отменено. Кнопки завершения/отмены ведут через ту же проверяемую карточку; событие не стирается из истории. Старые события M1–M3b при первом подтверждении переводятся в новый формат.

В общем календаре доступны **месяц / повестка, «Сегодня», фильтр проекта**. Время показывается в зоне события; смена зоны по умолчанию не меняет заседание. Повестка ограничена первыми 500 совпадениями с явным предупреждением — уточните проект.

## 2. Напоминания

В поле задаются разные смещения в минутах до начала, например **1440, 60, 0**. Пусто — без напоминаний. Максимум 5 значений от 0 до 43200 (30 суток). Для «весь день» **отдельно укажите местное время напоминания**: оно не становится временем события. Неуказанное время автоматически не подставляется.

**«Напоминания»** в панели проектов открывает центр. Там отображаются актуальные/пропущенные, прежнее отменённое расписание, попытки уведомления, кнопки перехода к событию и «Отметить просмотренным». Последнее — явное действие пользователя, не вывод по ответу ОС.

### Пока работает служба

- Проверка расписаний идёт фоново, примерно каждые 5 секунд; это не система реального времени. Один запрос системного показа может занимать до 20 секунд.
- **При закрытом браузере служба продолжает проверять расписания.** При остановке службы, выключении или сне ноутбука доставки нет.
- Системные уведомления Windows включаются отдельно в настройках секретаря. Используется штатный PowerShell/.NET WinForms NotifyIcon с общим текстом без названий дел. Установка сторонней службы/автозапуска не требуется. Возможность показа зависит от политик PowerShell, Windows, пользовательской сессии, «Фокусировки внимания» и разрешений уведомлений.
- Кнопка уведомления не открывает событие автоматически: откройте приложение и центр. Уведомление не является доказательством показа/прочтения. При блокировке/ошибке запись остаётся в центре.
- В серверном предпросмотре и вне Windows нативный показ отключён; это не ошибка календаря.

### Сон, перезапуск и защита от повторов

Срабатывание записывается в SQLite **до** попытки системного уведомления. После перезапуска уже обработанное расписание не рассылается повторно. При перерыве регулярной проверки более 45 секунд или первом запуске все уже наступившие напоминания отмечаются пропущенными в центре, **без массового системного повтора**. Часы ОС не исправляются автоматически; после их скачка применяется та же консервативная политика.

Изменение даты, времени, зоны, смещений или статуса создаёт новую версию расписания; прежнее не срабатывает, прежние записи помечаются отменёнными. Простая правка названия/заметки не создаёт повторного напоминания о том же моменте. Нативные уведомления, уже переданные ОС, отозвать гарантированно нельзя.

При аварии между записью попытки и вызовом ОС уведомление может не появиться — приложение **не повторяет его слепо**, чтобы не создавать дубли. Центр остаётся источником учёта. Ошибка записи не считается успешным срабатыванием.

Центр показывает до 500 записей, сначала актуальные непросмотренные; отмечайте их, чтобы увидеть следующие. Просмотренные/устаревшие записи могут очищаться при превышении 10000; актуальные непросмотренные молча не удаляются. Нагрузочные испытания больших календарей/центра ещё не проведены.

### Архив

Архивирование с будущими событиями требует выбора: **оставить действующими** или **отменить будущие**. Перед подтверждением показаны конкретные события. В первом случае они остаются в общем календаре/повестке и продолжают напоминать; во втором прежнее расписание аннулируется, события остаются в истории. Восстановление проекта не возобновляет отменённые события автоматически.

## 3. Версии документов

«Документы» → **«История правок материалов»**:

- переходы редакций, время, страховочная копия, SHA до/после;
- просмотр извлечённого текста «до»/«после» порциями по 20 фрагментов, с координатами; это не визуальный рендер Word;
- скачивание исходных байтов обеих редакций;
- **«Вернуть до/после…»** → кандидат/diff/SHA → обычное отдельное подтверждение.

Возврат создаёт **новую текущую редакцию из точных сохранённых байтов**. Не переписывает историю, старые цитаты, внешний оригинал или прежние `.blob`. Для DOCX не выполняется повторная строковая замена: возвращаются исходные байты выбранной версии. Перед применением обязательна страховочная ZIP-копия, проверяются ревизия и SHA текущего материала. Историческая версия также проверяется по SHA. Если она уже совпадает с текущей — явное «изменений нет».

Возврат доступен для цепочки, у которой есть единственный текущий прикреплённый материал. Убранная из проекта или неоднозначная цепочка не восстанавливается скрыто: скачайте и прикрепите нужный материал явно. После возврата **«Прочитать»** заново. Архив доступен только для просмотра/скачивания.

## 4. Печать

### TXT / MD / HTML

У материала — **«Печать…»**, у текстового результата — «Открыть» → «Печать…». Сначала безопасный текстовый предпросмотр, затем отдельная кнопка **«Открыть диалог печати»**. До неё можно отменить без обращения к печати.

Импортированный HTML показывается **как текст разметки**, не исполняется и не рендерит внешние ресурсы. Также можно сохранить печатное HTML-представление: весь пользовательский текст экранирован, без скриптов. Это безопасная печатная форма, не обещание повторить исходную HTML-вёрстку.

Предпросмотр материалов ограничен 100000 символов UTF-8; более крупный файл скачайте для внешнего редактора. После вызова `window.print()` статус только «диалог запрошен». Ни отмена, ни возврат функции не означают «распечатано». В автоматическом Chromium сам вызов подменён счётчиком, настоящий системный диалог проверяется на Windows.

### DOCX

Результат → **«Открыть DOCX для печати…»** → проверка SHA/предупреждений → подтверждение. Для импортированного DOCX — «Печать…» → подтверждение открытия редактором.

Windows получает запрос открыть **отдельную копию** в `projects/<pid>/temporary/…docx`. Неизменяемый артефакт результата и управляемый `.blob` редактору на перезапись не выдаются. Сохранённые в этой внешней копии правки сами не становятся новой версией проекта — их нужно импортировать явно.

При отсутствии ассоциации/редактора или ошибке — предложение сохранить файл; успешный запрос ОС не доказывает открытие приложения или печать. Импортированный контейнер с обнаруженными макросами/бинарными вложениями/внешними relationships автоматически редактору не передаётся. Это ограниченный preflight, **не антивирус и не гарантия безопасности документа**.

На целевом ноутбуке по сообщению пользователя нет Word/LibreOffice. **LibreOffice не устанавливаем.** Там проверяется корректный запасной сценарий. Визуальная вёрстка/офисная печать DOCX остаются согласованно отложенными, пока нет редактора. Открытые копии в temporary автоматически не удаляются и в backup не входят; важные изменения сохраните/импортируйте отдельно.

## 5. Сохранённые функции и границы

Сохранены чат B/D, отдельная C, история/отмена/usage, документы TXT/MD/DOCX/PDF с текстовым слоем, поиск и точные исторические цитаты, подтверждаемые правки и DOCX-черновики, резервные копии/restore. Подробная инструкция принятой базы — `README-M3b.md` (историческая, её разделы «ещё нет напоминаний» относятся к M3b, не M4).

Документы/SQLite/индекс/ZIP не зашифрованы; DPAPI защищает ключ текущего пользователя, не всю папку и не от программ с его правами. Ключ вводится только локально и не входит в архив программы. API должен слушать только 127.0.0.1 при обычном запуске; режим `--preview` исключительно разработческий. Никаких cookies/ключей/профилей браузера в отчёты.

В M4 не входят: повторяющиеся события, автозапуск Windows, OCR, правовой веб-поиск, EXE, локальная LLM, голос, отправка писем/подача документов, произвольные инструменты ОС. Остановка службы не притворяется работающим напоминателем. Процессуальные сроки и источники не получают автоматический статус юридически проверенных.

## Проверка и документы

`python -m pip install -r requirements-dev.txt` → `python -m pytest -q`.

- `TEST-REPORT.md` — фактические результаты текущей сборки.
- `WINDOWS-ACCEPTANCE-M4.md` — сценарии целевой приёмки, включая сон/браузер/отмену печати.
- `API-M4.md` и `API.md` — новые маршруты и прежний двухшаговый upload-контракт.
- `NEW-DEFECTS-M4.md` — новые дефекты/усиления и ограничения отдельно.
- `ACCEPTANCE-M3b.md` — запись о принятой базе **по отчёту пользователя**, не повторная проверка разработчиком ноутбука.

Службу оставляйте запущенной; закрытие браузера её не останавливает. Остановка — `stop.bat`/Ctrl+C. При проверке штатное завершение может ждать до 20 секунд окончания запроса уведомления.
