### Три пропуска на Linux

1. Настоящий Windows junction/reparse.
2. Настоящее шифрование/расшифрование Windows DPAPI.
3. Настоящий Windows Job Object: дочерний процесс ставит лимит и должен получить MemoryError при попытке выделить 800 МиБ.

Windows-ветка лимитов написана, но **её фактическая работа здесь не установлена**. Основные тесты извлечения при запуске на Windows также проходят через этот механизм. Если ОС не разрешает Job Object/назначение процесса, чтение должно завершаться явной ошибкой, без отключения защиты.

## Воспроизведение

```text
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Для браузера нужны отдельно Playwright/Chromium. Каждый сценарий запускается на **отдельном чистом тестовом пространстве**, не на данных пользователя. Пример:

```text
python -m uvicorn tests.mock_server:factory --factory --host 0.0.0.0 --port 8767 --no-access-log
node tests/ui_m3.cjs
```

Каталог mock-сервера задаётся переменной `YURIY_TEST_RUNTIME` (по умолчанию `~/yuriy-m2-browser-runtime`). Между сценариями остановите тестовый сервер и выберите новый тестовый каталог. В этой среде NODE_PATH указывал на отдельно установленный Playwright. Это инструменты разработчика, не часть обычной установки.

Обычный `start.bat` НЕ запускает mock-провайдер или preview; используется реальный OpenAI-адаптер, привязка 127.0.0.1.

## Границы проверки и риски

- Пользователь подтвердил работоспособность M2, но это не детальный Windows-отчёт и не проверка M3a. Новый BAT/подпроцесс/FTS5/Job Object/PDF на Windows ожидают локальной проверки.
- Нет реального ключа/аккаунта для проверки ответа SprutDock с документами. Формат запроса и передаваемый контекст проверялись mock-транспортом. Юридическая корректность вывода модели не доказана.
- Извлечение PDF не равно OCR: графика и порядок таблиц могут потеряться. На странице с некоторым текстом могут оставаться нераспознанные визуальные сведения. DOCX извлекается не полностью при дополнительных частях/разметке; предупреждения обязательны.
- Поиск лексический, не морфологический/семантический. Для общего вопроса совпадений может не быть — передаётся начало с явной отметкой. Это не исчерпывающий подбор доказательств.
- Цитаты/метки в ответе модели автоматически не валидируются по тезисам. Сохранённые фрагменты показывают реальные данные подготовки запроса, не подтверждают приём провайдером и не дают статуса правовой проверки.
- Фиксированный процесс с лимитами — не sandbox прав доступа. Он работает с правами текущего пользователя. Уязвимости парсеров/Windows-ограничения требуют дальнейшей проверки; заведомо вредоносные материалы использовать нельзя.
- Таймаут обработчика протестирован имитацией TimeoutExpired; CPU/память-пределы не подвергались отдельному нагрузочному исчерпанию в Linux. Прерывание питания не тестировалось.
- Индекс содержит незашифрованный извлечённый текст, не входит в ZIP и строится заново после restore. Исторические цитаты входят в основной backup. Нельзя называть удаление записи в UI безопасным стиранием.
- Перед использованием готового текста/поиском/контекстом исходная копия проверяется по SHA-256. Повторные проверки больших материалов дают дисковую нагрузку; масштабная отзывчивость на сотнях PDF не измерялась.
- Лимит общего контекста символьный, не токенизатор модели. Без разрешения новых фрагментов прежние ответы/цитаты текущей переписки всё равно могут передаваться в истории.
- Отсутствуют операции агента с исходниками, генерация DOCX, подтверждения правок, отдельная C-проверка, юридические веб-источники, OCR, напоминания и прямая офисная печать.

Итог: **готово к локальной проверке первой части M3** на неконфиденциальных копиях; полная приёмка Windows/V1 не заявляется.
