# Локальный API базы M3b (сохранён в M4)

**Новые маршруты 0.5.0-m4 — в API-M4.md.** Ниже унаследованный контракт загрузки, документов, чата, C и результатов.

Это внутренний API локального интерфейса, не публичная удалённая служба. Обычный запуск — loopback:8765. Кроме `/api/health`, API требует текущий `X-Yuriy-Token`, выдаваемый локальной странице. Проверяются Host/Origin; токен не передавайте в чаты/отчёты. Примеры ниже — структура запросов, не реальные ID. Все ID берутся из ответов службы.

Ошибки: обычно 400 для неверных входов, 409 для конфликтов/истёкшего предпросмотра, 403 для границы доступа; тело `{ "detail": "…" }`. Во время генерации операции записи блокируются. После изменения/генерации перечитывайте состояние, не переиспользуйте старую ревизию.

## Состояние

`GET /api/state` → `{revision, state}`. `PUT /api/state` принимает `{revision, state}`. Ревизия целочисленная, проверяется сервером; при конфликте загрузите актуальное состояние и согласуйте изменения. Не перезаписывайте его вслепую. Серверные ответы, операции и артефакты защищены от подмены обычным PUT.

## Важный двухшаговый контракт загрузки

1. `POST /api/projects/{pid}/files?name=<URL-encoded filename>`: **сырые байты**, не multipart. До 25 МБ. Ответ — метаданные `{id,name,size,sha256,pinned,ext,meta}`. Файл записан и зарегистрирован, но **ещё не связан с documents проекта**. Этот POST сам ревизию state не увеличивает.
2. Получите актуальный `{revision,state}`. Добавьте возвращённые метаданные в `state.projects[…].documents` соответствующего проекта. `PUT /api/state` с этой ревизией. Только теперь материал прикреплён. UI выполняет оба шага.
3. `POST /api/projects/{pid}/documents/{fid}/index`: локальное извлечение. Попытка индексировать непривязанный fid отклоняется как «не закреплён». Загрузка не означает извлечение или отправку модели.

При конфликте второго шага **не загружайте файл повторно**: получите свежий state, проверьте наличие fid и добавьте уже выданные метаданные один раз. При оборванной связи с неизвестным исходом сначала сверяйте состояние; автоматического удаления незавершённых загрузок нет. Зарегистрированный, но не прикреплённый файл может остаться в хранилище/backup.

`GET /api/projects/{pid}/files/{fid}` скачивает текущий прикреплённый материал. Предыдущие редакции скачиваются через журнал операций, а не этот маршрут.

## Чтение и поиск

- `GET /api/projects/{pid}/documents` — статусы.
- `GET /api/projects/{pid}/documents/{fid}/preview?offset=0` — порция до 20 фрагментов `chunks[{kind,number,segment,text}]` и метаданные; это не весь документ.
- `GET /api/projects/{pid}/document-search?q=…` — до 20 лексических совпадений.

## Правка материала

`GET /api/projects/{pid}/documents/{fid}/edit-source`: для TXT/MD возвращает текст и метаданные, для DOCX только метаданные/формат.

`POST /api/projects/{pid}/documents/{fid}/edit-plan`:

- TXT/MD: `{ "text": "полный новый текст" }`;
- DOCX: `{ "find": "однозначный фрагмент", "replace": "новый текст" }`.

Ответ содержит `planId,kind,projectId,fileId,revision,oldSha256,newSha256,before,after,diff,warning,expiresInSeconds`. План связывается с текущей ревизией при подготовке; произвольные пути/байты подтверждения не принимаются. Ограничения форматов — README.

## DOCX-результат

`POST /api/projects/{pid}/results/docx-plan`:

```json
{"title":"Название","text":"Основной текст [УТОЧНИТЬ]","sourceMessageId":"ID сохранённого ответа, необязательно"}
```

Без sourceMessageId источники не приписываются. Ответ — planId, kind=result, revision, name, newSha256, after, sourceCount, warning и срок. Полный DOCX доступен до подтверждения; текстовый after не включает служебные приложения/чек-лист.

## Общий жизненный цикл планов

- `GET /api/operations/{planId}/preview-file` — точные байты кандидата; скачивание не подтверждает запись.
- `POST /api/operations/{planId}/confirm` с `{ "confirmed": true }` — отдельное локальное подтверждение. Успех: `{operation,revision}`.
- `POST /api/operations/{planId}/discard` — забыть план.

Срок 600 секунд, максимум 10 планов/64 МБ кандидатов в памяти. При перезапуске/restore планы теряются. Одноразовые: после начала попытки коммита план может быть израсходован даже при ошибке записи. Новый план требует нового просмотра. До правки обязательна страховочная копия; до/после неё проверяются SHA.

**Потеря HTTP-ответа не означает откат коммита.** Прочитайте state: `project.operations[].confirmationId == planId` — квитанция сохранённой операции. UI сверяет её после ошибки связи. Не создавайте новую правку/результат до сверки. Повтор confirm сам не создаёт второй коммит: израсходованный план отклоняется.

- `GET /api/projects/{pid}/operations/{operationId}/revision-file?which=before|after` — проверенные по SHA байты редакции.
- `GET /api/projects/{pid}/results/{resultId}/file?format=docx|txt` — сохранённый результат; TXT только основной текст. По умолчанию docx.

## Явная проверка C

`POST /api/check`:

```json
{
  "requestId":"новый UUID",
  "projectId":"ID проекта",
  "threadId":"ID обсуждения",
  "messageId":"ID проверяемого ответа B/D",
  "excerpt":"точный весь ответ либо уникальный фрагмент",
  "revision":42,
  "confirmed":true,
  "documentsConsent":true
}
```

Перед этим C должна быть задана/разрешена в настройках. documentsConsent обязателен при наличии исторических цитат; без цитат можно не передавать. excerpt не является произвольным новым ответом: проверяется точное уникальное вхождение, с сопоставлением CRLF браузера. Только complete/limited B/D. Весь JSON-контекст C ограничен 40000 символов без молчаливого усечения. При отказе контекста провайдер не вызывается.

Ответ `{requestId,reused}`. Повтор того же requestId и параметров читает прежнюю генерацию, не отправляет её повторно; для отличающихся параметров — конфликт. События и отмена общие с чатом:

- `GET /api/chat/{requestId}/events` — поток SSE;
- `POST /api/chat/{requestId}/cancel`;
- `GET /api/chat/active` — активный запрос.

Отчёт C — отдельное assistant-сообщение `kind=verification,tier=C,verifiesMessageId,checkScope`, с собственным конечным статусом, usage и диагностикой. checkScope включает SHA исходного ответа, answerStatus, start/end, checkedChars/totalAnswerChars, wholeAnswer/sourceCount; priorConversationIncluded=false, legalPrimarySourceVerification=false. Позиции — индексы Python Unicode-строки, не байты и не UTF-16 offsets JavaScript. Снимки источников не обновляются с диска. Статус complete не означает юридическую верификацию.

## Настройки и копии

`GET/POST /api/models/settings`: унаследованные B/D/endpoint/лимиты плюс modelC,verificationEnabled,maxOutputTokensC. Лимит C/D null — наследование общего; иначе 128–8192. Ключ никогда не возвращается GET. Флаг verificationEnabled — разрешение функции, не автоматический вызов.

`POST /api/backup` скачивает ZIP и возвращает имя в X-Backup-Name. `POST /api/restore` принимает сырые байты ZIP и заголовок `X-Confirm-Restore: yes`. Восстановление заменяет пространство, аннулирует планы/активные объекты и очищает индекс; сначала обязательна страховочная копия. Не используйте рабочее пространство для экспериментов с restore.
