# Windows-приёмка M4 · 0.5.1-m4

**Статус этого файла: план, не отчёт об исполнении.** Цель — Windows 10 Pro 22H2 пользователя. Проверять на вымышленном тестовом проекте и отдельной копии данных. Рабочую M3b не удалять до приёмки.

## A. Поставка и запуск

1. В 0.4.0 создать ZIP и отдельную копию пространства. Остановить службу.
2. Распаковать M4 в новую папку. В PowerShell из этой папки проверить манифест:

```powershell
$lines = Get-Content -LiteralPath .\RELEASE-MANIFEST.sha256
foreach ($line in $lines) {
    $parts = $line -split '  ', 2
    $actual = (Get-FileHash -LiteralPath $parts[1] -Algorithm SHA256).Hash.ToLower()
    if ($actual -ne $parts[0]) { throw "Не совпал файл: $($parts[1])" }
}
"Совпало файлов: $($lines.Count)"
```

3. `install.bat`, затем `start.bat`. Проверить health **0.5.1-m4**, обычную привязку 127.0.0.1:8765, отсутствие второй службы.
4. Установить dev-зависимости в новой `.venv` и запустить:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Зафиксировать фактические passed/skipped, не переносить Linux-результат на Windows. Тесты не должны сами вызывать настоящий редактор или показывать уведомления: эти обращения там подменены.

5. Проверить проекты, материалы/историю, результаты, ключ локально и настройки B/C/D. Ключ/токены в отчёт не копировать.

## B. Событие по поручению — ТЗ №16

1. «Чат» → «＋ Дата в календарь». При первом использовании подтвердить **Europe/Samara**; отдельно разрешить системные уведомления, если будете проверять их.
2. Ввести «Завтра заседание в 14:30». До сохранения проверить абсолютную дату относительно зоны, проект, тип, время/зону, происхождение. В карточке подтверждения проверить UTC (для Samara на 4 часа раньше), затем подтвердить. Убедиться в календаре после reload и перезапуска службы.
3. Повторить «Послезавтра отправить письмо» — без придуманного времени, весь день, startsAt=null. Отменить карточку: события не появляется.
4. «Срок обжалования через 15 дней» — не должен превратиться в автоматически рассчитанную/утверждённую дату. Дата требует уточнения, предупреждение о черновике срока видно.
5. Две разные даты/дата без года — уточнение. Неверная дата/время — отказ. Неизвестная IANA-зона — отказ. При необходимости проверить Europe/Berlin 2026-03-29 02:30 (несуществующее) и 2026-10-25 02:30 (нужно выбрать вхождение).
6. Взять предложение из сохранённого сообщения и из извлечённого документного фрагмента. Сверить происхождение, SHA/версию/координаты. Перенос не означает подтверждение фактов.
7. В двух окнах: открыть карточку в первом, изменить проект во втором, подтвердить старую — конфликт, без дубликата. Повторное подтверждение израсходованного плана не создаёт копию.
8. Отредактировать старое событие M3b: время по-прежнему Samara, уведомления не включены сами; после явной настройки и подтверждения доступно новое расписание.

## C. Напоминания, закрытый браузер и сон — ТЗ №17

Фактический нативный показ — обязательная отдельная проверка здесь. API-запись requested-not-confirmed не доказывает появления уведомления.

1. Создать временное событие на несколько минут вперёд, смещение `0`. Подтвердить. Дождаться срока: в центре запись, счётчик/переход к событию. Если ОС разрешила — системный показ. Записать **раздельно**, появился ли он и что в центре.
2. Повторить, закрыв все вкладки Юрия, **не останавливая окно службы**. После срока открыть браузер — запись сохраняется, уже обработанное напоминание повторно не рассылается.
3. Создать новое событие на несколько минут вперёд. Усыпить ноутбук до срока, проснуться после него. При работающей до сна службе дождаться возобновления: пропущенное в центре, без шквала старых системных сообщений. Центр обновляется кнопкой «Обновить»; кнопка в панели опрашивается примерно раз в 15 секунд.
4. Создать ещё одно, остановить службу до срока и запустить после. Пропущенное сохранено при первом проходе, не выдано за доставленное во время остановки. Перезапуск снова не создаёт массовый повтор.
5. Изменить время будущего события до наступления старого: старое расписание не срабатывает, новое срабатывает. Повторить с отменой/выполнением. Правка только названия не дублирует уже сработавшее напоминание.
6. Событие «весь день»: без явного времени напоминания и с непустыми смещениями — отказ; с указанным временем — напоминание в нём, при этом событие остаётся календарной датой.
7. Выключить системные уведомления в секретаре: центр работает, системного запроса нет. Если корпоративная политика/фокусировка блокирует показ — отметить ограничение, не ставить PASS фактическому показу.
8. «Отметить просмотренным», backup/restore тестового пространства, перезапуск: отметка сохраняется, уже обработанное не повторяется. Restore делать только на тестовой копии, он заменяет всё пространство.

Нативный механизм использует штатный PowerShell/.NET NotifyIcon и общий текст без названий дел. Отдельного пункта приложения «Юрий» в списке системных разрешений может не быть. Не ослабляйте защитные политики ОС автоматически ради теста: сообщите об ограничении.

## D. Архив с будущим заседанием — ТЗ №18

1. Архивировать проект с будущим действующим событием/напоминаниями. Проверить список, выбрать **оставить**, подтвердить.
2. Проверить общий календарь/повестку и фильтр проекта: будущее заседание архива видно; напоминание остаётся действующим, переход открывает проект.
3. Вернуть проект, архивировать с выбором **отменить**. Событие не удалено, статус отменён, старого расписания нет. Возврат проекта сам его не возобновляет.

## E. Редакции документов

1. Две правки вымышленного TXT: список переходов/время/SHA/backup, просмотр/скачивание «до»/«после».
2. «Вернуть до…» → кандидат → подтвердить. Новый текущий fileId, прежние версии не изменены; скачанные байты совпали с выбранной версией (включая BOM/CRLF, если были).
3. Повторить на простом DOCX. Сравнить SHA точных байтов, а не только текст. Повторная строковая замена не выполняется. После возврата текст требует повторного «Прочитать».
4. Внешняя подмена текущих байтов между preview/confirm должна блокировать возврат; текущий материал не перезаписывается. Проверять только на тестовом пространстве.

## F. Печать и отмена — ТЗ №19

1. TXT-материал/текстовый результат: безопасный предпросмотр. «Отмена» до печати не вызывает системный диалог.
2. «Открыть диалог печати»: появляется настоящий системный диалог браузера. Отменить его — нигде нет статуса «распечатано».
3. HTML с тестовым `<script>…</script>`: разметка видна как текст, не исполняется. Сохранённое печатное HTML-представление экранировано и открывается отдельно в браузере; печать через его диалог.
4. DOCX: подтверждение открытия отдельной копии. При отсутствии редактора/ассоциации — корректное предложение сохранить. Если Windows приняла запрос, но показала выбор приложения, не считать файл открытым или напечатанным.
5. **LibreOffice не устанавливаем.** Визуальная вёрстка и офисная печать DOCX согласованно отложены; этот пункт не записывать как выполненную печать.

## G. Регрессии и итог

Короткий живой B/C/D на вымышленной задаче при необходимости выполняется только с явным согласием на оплату. Проверить отмену/сохранение, цитаты и согласие, DOCX, ручной календарь, backup/restore; настройки лимитов не повышать автоматически. Браузерные scripts из tests запускаются только против mock-служб и чистых runtime, не рабочей 8765.

В итоговом `.md` указать: версия/ОС/Python, манифест/pytest, фактический показ уведомлений отдельно от центра, сон/перезапуск, архив/редакции/печать/отмена, ограничения и новые дефекты. **Статус «V1 принята» только после фактической приёмки и явного сохранения согласованного исключения по офисной печати.**
