# Новые дефекты и ограничения · M3b 0.4.0-m3b

Отдельный отчёт по разработке текущего этапа. Это не переоткрытие принятой M3a. Ниже различаются воспроизведённые ошибки, профилактическое усиление и ещё не выполненная приёмка. Исправления находятся только в новой сборке; установленная 0.3.1-m3a не менялась.

## D1. Нормализация CRLF браузером

**Обнаружено и исправлено; серверный регрессионный тест проходит.** HTML textarea превращает CRLF в LF. Наивная запись TXT меняла бы все переносы; точный поиск выбранного фрагмента для C мог бы отвергнуть исходный текст.

Теперь редактор сохраняет BOM и единообразный CRLF исходного TXT, а выборка C сопоставляется с нормализованной строкой и переводится обратно в точные координаты оригинала. В C передаётся оригинальный фрагмент, не переписанный текст. Смешанные переносы не считаются автоматически восстановленными; изменения проверяются по кандидату/SHA. Тест: `test_crlf_text_edit_and_check_excerpt_coordinates`.

## D2. Изменение материала во время страховочной копии

**Воспроизведено искусственным изменением на диске; исправлено.** Одной проверки SHA перед созданием backup недостаточно: файл может измениться во время копирования.

Добавлена повторная проверка размера/зарегистрированного SHA/байтов перед записью новой редакции. В тесте исходник изменяется внутри подменённой функции backup; подтверждение завершается 409, текущая ссылка не меняется. Тест: `test_source_changed_during_backup_rejected`.

Это не исключает любую гонку с произвольной сторонней программой, которая одновременно пишет в управляемую папку после последней проверки. Не редактируйте `.blob`/SQLite вручную при работающей службе. Защита рассчитана на локальное приложение с единственным управляемым писателем, а не враждебную файловую систему.

## D3. Неизвестный исход подтверждения при обрыве HTTP

**Профилактическое усиление; транспортный обрыв после коммита отдельно не симулировался в браузере.** Сервер мог успешно сохранить операцию, а браузер — не получить ответ. Простое предложение «повторить» могло привести пользователя к созданию ещё одного результата через новый план.

В неизменяемом журнале теперь сохраняется `confirmationId=planId`. При ошибке confirm UI перечитывает состояние и ищет квитанцию; при её наличии показывает сохранение без повторной записи. Если связь не восстановилась — предлагает проверить историю/результаты, не обещает откат. Повтор confirm с израсходованным планом сам не выполняет второй коммит. Сохранение квитанции проверено `test_confirmation_receipt_and_artifact_template`; общий сценарий подтверждения проходит в Chromium.

## D4. Опасные/неподдерживаемые DOCX и некорректные XML-символы

**Усиление в ходе реализации; отрицательные тесты проходят.** Добавлен отказ для внешних relationships/шаблонов, макросовместимых контейнеров, встроенных объектов и сложной разметки, а также недопустимых XML-символов. Замена фразы, разбитой между run, не объединяет форматирование молча: получает отказ. Тесты: `test_docx_external_relationship_and_invalid_xml_rejected`, `test_docx_table_edit_and_split_run_rejection`, `test_docx_edit_is_conservative_and_preserves_other_parts`.

Это консервативный редактор, не универсальный sanitizer и не антивирус. Ограничение процесса по ресурсам не является файловой песочницей по правам ОС.

## D5. Унаследованные метаданные шаблона DOCX

**Исправлено до выпуска.** Генерируемому документу явно задаются текущие created/modified и автор/last_modified_by «Юрий», чтобы не наследовать чужие даты/автора из библиотечного шаблона. Добавлены предупреждение о неполном статусе исходного ответа и сохранение этого статуса в происхождении результата. Автор, год и пометка в колонтитуле проверяются тестом `test_confirmation_receipt_and_artifact_template`. Корректность часов зависит от ОС.

## Что не объявляется устранённым или проверенным

- **M3b на Windows, реальный C, DPAPI/junction/Job Object текущей сборки и оформление в Word:** приёмка ещё не выполнена. Пропуски не превращены в PASS.
- **Сложные DOCX и PDF-правки:** намеренно не поддерживаются. Многозначные/разбитые run отклоняются, внешние оригиналы не перезаписываются.
- **C:** получает исходный вопрос, выбранный ответ и старые цитаты, но не всю переписку/инструкцию проекта и не актуальные правовые базы. Complete не подтверждает юридическую верность.
- **Шифрование/стирание:** рабочие документы, цитаты, индекс и ZIP не зашифрованы; безопасного стирания и полной защиты от DNS rebinding нет. Токен/Host/Origin не заменяют защиту ОС.
- **Остаточные файлы/объём:** после сбоя между файловой записью и коммитом могут остаться неиспользуемые файлы. Автоочистки старых редакций/ZIP нет; масштабные замеры диска/памяти не проводились.
- **Upload API:** POST файла и прикрепление в state — два шага, не единая транзакция. Это явно документировано в API.md; UI выполняет оба. Неприкреплённый файл не индексируется и может остаться в хранилище.
- **Предпросмотр/печать:** текстовый preview не показывает реальную вёрстку Word; требуется проверка в редакторе. Фактическая печать приложением не подтверждается.

На финальном серверном прогоне нет падающих автоматических тестов. Это не заявление об отсутствии иных дефектов.
